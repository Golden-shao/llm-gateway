Features

为生产而生的网关，为学习而生的工程

每个特性都对应一个真实的运维场景——这也是一个从零学习 Kubernetes 与 AI 基础设施的完整载体。

统一认证

客户端只需携带网关密钥（Bearer），上游真实密钥只存在于服务端，永不泄露给调用方。

令牌桶限流

按客户端密钥限制每分钟请求数，防滥用、防突刺；跨副本精确限流预留了 Redis 扩展点。

SSE 流式透传

stream: true 的对话请求原样透传事件流，端到端低延迟，与大模型原生输出体验一致。

结构化日志

记录时间、客户端哈希、路径、延迟与估算 token——不落盘明文密钥，便于审计与成本分析。

K8s 原生部署

Helm Chart 一条命令部署：Deployment、Service、探针、资源限制、HPA 自动扩缩开箱即用。

CI/CD 自动化

GitHub Actions 自动跑测试、构建镜像、推送 GHCR——每次提交都是一次真实的发布演练。

Architecture

请求如何穿过网关

客户端只面向网关一个地址；网关完成认证、限流后，用服务端持有的上游密钥发起调用，流式响应原样回传。

示意：网关是唯一入口，上游密钥只存在于服务端；副本数由 HPA 按 CPU 自动伸缩。
Quickstart

五分钟跑起来

选一种方式：本机 Docker 立即可用；或起一个 kind 集群体验完整 K8s 部署。

# 构建镜像（国内网络可加 --build-arg PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple）
docker build -t llm-gateway:latest gateway/

# 运行：用你自己的上游密钥替换 sk-your-upstream-key
docker run -d --name llm-gateway -p 8080:8080 \
  -e GATEWAY_UPSTREAM_API_KEY=sk-your-upstream-key \
  -e GATEWAY_GATEWAY_API_KEYS=dev-key \
  llm-gateway:latest

# 验证
curl -H "Authorization: Bearer dev-key" http://localhost:8080/v1/models
# 本地集群
kind create cluster --name llm-gateway

# 部署（网关密钥与上游密钥通过 Secret 注入）
helm install llm-gateway deploy/helm/llm-gateway \
  --set secret.create=true \
  --set secret.upstreamApiKey=sk-your-upstream-key \
  --set secret.gatewayApiKeys=dev-key

# 访问
kubectl port-forward svc/llm-gateway 8080:8080
curl http://localhost:8080/healthz
API Reference

接口与配置

接口保持 OpenAI 兼容，客户端代码零改动即可接入。

方法路径说明
POST/v1/chat/completions对话补全；请求体含 stream: true 时以 SSE 流式透传返回
GET/v1/models上游模型列表（网关侧带 TTL 缓存）
GET/healthz存活探针，返回 {"status":"ok"}
环境变量（前缀 GATEWAY_）默认值说明
UPSTREAM_BASE_URLhttps://api.openai.com/v1上游 OpenAI 兼容地址
UPSTREAM_API_KEY（空）服务端调用上游的密钥，只存于服务端
GATEWAY_API_KEYS（空）客户端网关密钥，逗号分隔
RATE_LIMIT_RPM60每客户端密钥每分钟请求上限
MODELS_CACHE_TTL60/v1/models 缓存秒数
